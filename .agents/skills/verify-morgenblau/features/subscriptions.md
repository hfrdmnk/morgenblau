# Subscriptions and Sources

A reader follows RSS or Atom feeds and Standardfeed publications. Adding one writes a subscription record to the reader's PDS first and then mirrors it into the local index; a fetch job loads its entries. The Sources page lists feeds and newsletters, and the header's `Add a source` dialog finds and adds feeds. Each feed on `/sources` and its detail page opens the same sheet to rename, retag, mark primary, switch a YouTube channel's Shorts and delete it; newsletters keep an actions menu for renaming, tags and stopping. Bulk import and export live in [import-export](./import-export.md).

Help article: none

## Sub-features

- `sources-page` `/sources` (`frontend/src/pages/sources.tsx`) lists `Feeds` and `Newsletters` (plus `Stopped newsletters` when any); each list has a `Try again` on load failure. `FeedHealth` shows a red dot after the URL only for unavailable feeds, with an accessible status label; healthy and unchecked feeds have no dot. Generated feeds add a quiet health line ([generated-feeds](./generated-feeds.md)). `FeedList` polls so recovery appears without reloading. No feeds shows `No feeds yet. Import feeds`.
- `source-detail` `/sources/<rkey>` and `/sources/newsletters/<id>` (`frontend/src/pages/source.tsx`, `newsletter-source.tsx`), reached by a source's title on `/sources` or the source name in the reader. The header shows the facts line, tags and the same health as the list: `Posts aren’t fetching right now` with the red dot for an unavailable feed, and the generated-feed note. Its posts open the reader with `Back to source`.
- `edit-sheet` `Edit <title>` (`EditSourceSheet` in `frontend/src/components/add-source-dialog.tsx`) on every feed row and feed detail header opens the add sheet on that feed: textbox `Name` in the header (Enter saves), `Latest posts`, `Add a tag`, `Exclude Shorts` for a YouTube channel feed, `Primary`, `Save changes` (disabled until something differs) and `Delete source`, which confirms, then DELETEs it (from the detail page it returns to `/sources`). One save PATCHes only the changed fields and toasts `Source updated`. A source removed meanwhile answers `This source is no longer in your sources.`
- `source-menu` `Actions for <title>` (`frontend/src/components/source-menu.tsx`) on every newsletter row and header: `Rename` and `Edit tags` open dialogs that PATCH it. `Stop newsletter` (confirmed) or, once stopped, `Resume newsletter`, since v1 never deletes newsletters. A source removed meanwhile answers `This source is no longer in your sources.`
- `add-dialog` `Add a source` (`frontend/src/components/add-source-dialog.tsx`, in the app header on every app page) is a sheet: from the right on wide screens, a swipeable bottom sheet on phones. It takes `Website or feed URL`; `Find feeds` lists `Available feeds`, plus a `Profile` row when the site publishes SocialSpec files. Each feed opens its own screen with its title as textbox `Name` in the header, `Latest posts` (up to three), `Add a tag`, `Exclude Shorts` for a YouTube channel (off by default; on, it follows the channel's `playlist_id=UULF…` feed and previews it) (a combobox suggesting existing tags), a `Primary` switch and `Add to sources`; once followed it reads `In your sources` with a secondary `Remove from sources`. A post opens its own screen titled with the post, dated in the subline, with the feed's body, `Load full article` and `Read original`, like the reader. `Back` returns. The profile screen shows about text, contact and the sites it follows, listed like `Available feeds`; each opens that feed's screen. Every add toasts `Source added` with an arrow; the whole toast is a button that closes the sheet and opens `/sources/<rkey>`. Toasts sit bottom-left on wide screens and top on phones. When resolve finds nothing, the sheet offers to generate a feed instead ([generated-feeds](./generated-feeds.md)). The search screen also shows the private `Newsletter email address` with a copy button.
- `preview` `POST /api/subscriptions/preview` with `{feedUrl}` or `{publication}` returns `{items}`, the newest three posts with `url` and sanitized `contentHtml`; nothing is stored.
- `preview-article` `POST /api/subscriptions/preview/article` with `{url}` returns `{contentHtml}`, the readability-extracted post.
- `profile` `POST /api/subscriptions/profile` with `{url}` returns `{profile}` from the site's `/.well-known/about.md`, `contact.vcf` and `following.opml`, or `null`. The fixture origin serves all three.
- `resolve` `POST /api/subscriptions/resolve` with `{url}` returns `{candidates, existingSubscriptions}`.
- `add` `POST /api/subscriptions` with one source per request, `{"feedUrl":"..."}` (RSS) or `{"publication":"at://..."}` (Standardfeed); returns the record plus its `jobId`. Adding an existing feed returns its record without a `jobId`; a YouTube channel's `channel_id=UC…` feed and its `playlist_id=UULF…` feed count as the same feed (`SameYouTubeFeedURLs` in `internal/feedfinder`), here and in `resolve`'s `existingSubscriptions`. A missing URL answers `400` with field errors; a list body is `invalid json`. A source for a site the reader already follows under the other kind answers `409` `Pick either the RSS feed or the ATProto publication for a site, not both`, before any PDS write.
- `list` `GET /api/subscriptions`, `GET /api/subscriptions/{rkey}`, `GET /api/subscriptions/{rkey}/entries`, `GET /api/subscriptions/tags`.
- `edit` `PATCH /api/subscriptions/{rkey}` with any of `title`, `primary`, `tags`, `feedUrl`; a `feedUrl` change returns a `jobId`, and one that matches another subscription answers `409` `already subscribed to that feed`. One that moves onto a site followed as a Standardfeed publication answers the site `409` above.
- `remove` `DELETE /api/subscriptions/{rkey}`.

## How to reach it

- Browser: `/sources`, or the mode selector (`<mode>: choose mode`, then `Sources`). `Add a source` in the header of `/`, `/sources`, `/library` and `/settings/*`.
- API routes above (`internal/server/routes.go`).

## Drive and prove

Preconditions:

- Doctor exit `0`, `$V login $S`, browser signed in. `F` is the run's fixture origin (`fixtures.url` in `up`'s state). No public network is needed except for the Standardfeed step.
- The feed under test is `$F/feeds/valid.xml` (`Example Fixture Feed`, one entry dated a minute before each fetch and one from 2024), found from the site `$F/` alongside `$F/feeds/atom.xml`. Other fixture feeds below prove failure handling; [`tools/feed-fixtures.mjs`](../tools/feed-fixtures.mjs) owns the catalog. A task that names its own public feed may use it instead and record it in `$E/notes.md`.
- An add commits the PDS record before any fetch, so a bad feed URL yields a subscription whose fetch fails, not a refusal.

- **Dialog.** `click "getByRole('button', { name: 'Add a source' })"`: dialog `Add a source` with textbox `Website or feed URL`, a disabled `Find feeds`, and the `Newsletter email address`. `screenshot --filename=add-source-dialog.png`.

Open the profile: contact `hello@fixture.example.com` and two follows; `Example Latin-1 Feed` opens its feed screen; `Add to sources` there toasts, and back on the profile its row reads `Example Latin-1 Feed, In your sources` with a check. `Back`, open `Example Fixture Feed`: `Latest posts` lists its two entries. Type tag `Friends` and press Enter (or the enter icon `Add tag` inside the field), turn on `Primary`, click `Add to sources`: the row shows a check and its screen reads `In your sources` with `Remove from sources`, and `GET /api/subscriptions` shows `primary: true` and `tags: ["Friends"]`. Opening `Fixture entry published just now` shows its body; `Load full article` loads the fixture post page. `Remove from sources` turns the screen back into the add form. Clicking the `Source added` toast lands on `/sources/<rkey>`. `screenshot --filename=add-source-saved.png`.
- **Health and recovery.** After `GET /api/jobs/active` is `null`, `GET /api/subscriptions` reports `fetchStatus: "ready"` and a `lastFetchedAt` for the working feed; `/sources` shows no dot after its URL. Add `$F/feeds/unavailable.xml` (always `503`): its first failure reports `fetchStatus: "unavailable"` and `nextFetchAt`, and the page shows a red dot with an accessible automatic-retry label. For recovery, `curl -X POST $F/control/toggle/down`, add `$F/feeds/toggle.xml` and wait for its red dot. Then `curl -X POST $F/control/toggle/up`, move its retry eligibility into the past in the disposable DB only (`sqlite3 $E/run/morgenblau.db "update feeds set next_fetch_at='2000-01-01T00:00:00Z' where feed_url='$F/feeds/toggle.xml'"`) and call `POST /api/digest/refresh`. Wait for the job to finish and the page to poll: the dot disappears without navigation or reload. Capture both states and check a narrow viewport for overflow.
- **Odd feeds.** Add `$F/feeds/atom.xml`, `$F/feeds/stale.xml` and `$F/feeds/latin1.xml`: each is `ready`, and their entries include `Atom fixture entry published just now`, `Stale fixture entry from 2019` and `Grüße aus Zürich, café crème` (served as ISO-8859-1, stored as UTF-8). Add `$F/feeds/broken.xml` (malformed XML) and `$F/feeds/huge.xml` (over the fetcher's 5 MiB cap): each is `unavailable` with no entries, and `server.log` shows `parse feed` and `response body exceeds cap`. `GET "/api/digest?timezone=<the browser's zone>"` holds the fresh valid, Atom and ISO-8859-1 entries and never the 2019 one.
- **Fixture boundary.** Only the fixture origin is reachable. `POST /api/subscriptions/preview` for the decoy feed answers `502`, and `/profile` for the decoy answers `{"profile":null}`. ## Gotchas

- These are real writes to the run's own PDS, deleted with it by `down`.
- Fixture feeds are reachable only because `up` passes the fixture origin as `FEED_FIXTURE_ORIGIN`, which `loadLocalNetwork` (`internal/server/`) honors only beside a run's `PLC_URL` under `APP_ENV=local`. Other loopback ports, private addresses and redirects off the origin stay blocked; production ignores the variable.
- Favicon discovery keeps the default guarded client, so fixture feeds show the fallback icon and `server.log` warns `favicon discovery failed`. Not a failure.
- An API add without a `title` lists the feed under its site URL; the dialog sends the feed's title. An untitled feed that never fetched shows its feed URL (`127.0.0.1:<port>/feeds/unavailable.xml`); once a fetch sets its site URL it shows `127.0.0.1:<port>`, which every fetched fixture feed shares, so several `Edit …` buttons can share one name: drive the sheet on a titled feed.
- A fresh fixture entry is dated a minute before the fetch, so in the first minute after midnight it lands on the previous day.
- Standardfeed adds resolve the publication's identity over the network; a failure there is `blocked`, not `fail`.
- A session without the Standardfeed scope gets `403` with `code: "reauth_required"` on Standardfeed writes; the dev login's password session is not scoped this way.
- The dialog prefixes a bare host with `https://` before resolving (`frontend/src/lib/add-source.ts`).
