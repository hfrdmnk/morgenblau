# Frontend conventions

## Stack

- Bun only: `bun run <script>`, `bunx` for one-offs, never npm/npx/pnpm. CI rejects any other lockfile.
- Shadcn uses Base UI primitives from `@base-ui/react`; `components.json` holds the style.
- Basicons is the only icon source. Review icons for local SVG markup; runtime embed scripts are forbidden. `eslint.config.js` owns the import restriction. `components.json` names `lucide` only so shadcn installs resolve.
- Brand direction lives in `BRAND.md`; visual tokens live in `src/index.css`.

## Motion

- Motion is for feedback and temporary context, in keeping with `BRAND.md`'s calm character: nothing decorative, looping or attention-seeking. The `/__dev/styleguide` Motion section shows the rules in use.
- CSS transitions take their durations from the `--motion-duration-*` tokens and easing from `--ease-*` in `src/index.css`, and list the properties they transition instead of `transition-all`.
- Animate `transform`, `opacity` and `filter`. Size and position changes go through `motion`'s `layout`, or the keyframes the shadcn primitives already ship; never transition width, height or offsets by hand.
- Reduced motion is part of every animation: the tokens collapse under `prefers-reduced-motion`, CSS animations sit behind `motion-safe:` or `motion-reduce:`, and `motion/react` code reads `useReducedMotion()` and goes instant.
- Multi-stage choreography is a storyboard: a header comment listing each stage with its time, then a `TIMING` object and per-element config objects that hold every duration, easing and spring, never inline in JSX. `src/components/add-source-dialog.tsx` is the reference. The pattern is adapted from the Storyboard Animation guide in Josh Puckett's Interface Craft.
- `test/preload.ts` explains how `motion` runs under happy-dom.

## Adding shadcn components

- `bunx shadcn@latest add <name>` from `frontend/`. Never run `shadcn init` (it rewrites `src/index.css` tokens).
- The CLI writes into a literal `frontend/@/` directory; move wanted files to `src/components/ui/` and delete `./@`. CI's generated-component-path check enforces the tracked-file boundary.
- It may overwrite house components listed as registry deps. Review the diff and restore house versions; never pass `--yes` blindly.
- Replace any Lucide icons generated by shadcn with Basicons equivalents in the same change.

## PWA

- `vite.config.ts` and `src/pwa.test.ts` own static-asset precaching. Offline data sync remains outside scope.

## Lint

- `eslint.config.js` and the `lint` script in `package.json` own enforcement; fix violations in code.
- Shared hooks live in `src/hooks/`, since a component file may export only components.

## Loading

- A page shows its own skeleton from the first frame. Import pages eagerly; never put a generic "Loading" screen in front of one. A `Suspense` fallback is `null` or the page's `*Skeleton`, and `eslint.config.js` enforces that.

## API

- `api()` in `src/lib/api.ts` is the API boundary; `eslint.config.js` owns its enforcement. Review cancellable calls for a passed `signal`.

## Codebase hygiene

- fallow gates every commit through `.githooks/pre-commit` (only findings the changeset introduces block); config lives in `.fallowrc.jsonc`, and fresh clones activate hooks with `make hooks`.
- Run `bun run doctor` (react-doctor) at least once per feature branch before it merges. Treat its diagnostics as hypotheses to verify in the code, not verdicts.
- Whole-tree sweeps beyond the commit gate: `bunx fallow` (dead code, duplication, complexity, boundaries).

## Testing

- Fixtures follow the Testing rule in the root `AGENTS.md`. The `verify-morgenblau` skill says which checks a change needs.
